# The base rules

Every profile builds on these. Each rule has a stable ID that findings cite. `check` marks the rules
`tone check` decides, fully or in part; the rest is judgement.

Precedence, highest first: an explicit instruction in the request, rules files in context
(`~/.claude/rules/`, `.claude/rules/`), the profile, this base.

## Facts

### TONE-001 Only what is known (check: hedge words, as a note)

Write only what the draft or the given context states. A guess written as a fact, or softened into
"probably", "seems to", "should now work", "vermutlich", "sollte jetzt", is a finding. Unknown means
left out, or asked back as a question.

- Bad: "Das Problem lag vermutlich am Cache und sollte jetzt behoben sein."
- Good: "Der Export lädt große Rechnungen wieder vollständig." (only if verified)

### TONE-002 No promises the context does not hold

No dates, releases, versions or behaviour that nobody stated. "Fix comes with the next release" needs
a source in the context.

## Exposure: never written, in any audience

### TONE-010 Secrets (check)

Tokens, API keys, passwords, private keys, connection strings with credentials, signed URLs. Remove
them; never "mask" them partially.

### TONE-011 Personal data (check: emails, phone numbers)

Email addresses, phone numbers, postal addresses of people, unless the reader already has them and the
text cannot work without them. Name a person by role ("the reporter", "die Ansprechpartnerin beim
Kunden") when the name adds nothing.

### TONE-012 Other customers

No names, tenants, accounts or data of a customer the text is not about. In internal text about that
customer, fine.

### TONE-013 No blame

Describe what happened, not who caused it. "The import skipped rows with empty dates", not "X forgot
the empty dates".

### TONE-014 Not how it was made (check)

No mention of AI, Claude, agents, sessions, prompts or the tools used to produce the text or the work.

### TONE-015 No open security detail

A weakness that is not fixed yet is described by its effect only ("access check on exports
tightened"), never with the way to exploit it.

### TONE-016 No internal commercial detail

Prices, deals, discounts, contract terms only in internal text that is about them.

## Exposure: internal audience only

### TONE-020 Technical internals (check)

Code, code spans, file paths, function names, branches, commits, PR links, stack traces, log lines,
hostnames, IPs, service, repository and table names. External text describes the effect for the
reader instead. Internal text keeps only what the reader needs to act: one identifier beats a paste,
a link beats a log.

### TONE-021 Internal hosts (check, error)

A URL to localhost, a bare IP, a single-label host or a `.local`, `.internal`, `.lan`, `.corp`,
`.intranet` host in external text.

### TONE-022 Any other URL in external text (check, note)

The check cannot know which domains are public. The review decides: a link to the public product,
docs or the customer platform stays; a link to an internal tool (Linear, Jira, Grafana, a private
repository) goes.

## Audience

### TONE-030 Unknown audience is external

`external` or `internal`, from the caller. Not passed and not clear from context: `external`.

## Style

### TONE-040 Outcome first, one topic

The first sentence says the outcome or the point. One text, one topic. No restating the title.

### TONE-041 No filler (check)

No greetings, sign-offs, apologies, thanks-for-reporting boilerplate, hedging, "in order to",
"grundsätzlich", "im Prinzip".

### TONE-042 No AI tells (check)

No long dashes (— or a spaced –), "not just X but Y", "nicht nur … sondern auch", lists of three for
rhythm, "delve", "seamless", "leverage", "nahtlos", "ganzheitlich", emoji.

### TONE-043 Formatting per profile (check)

Headings, bullets, tables and bold only as the profile allows. Bold is never scattered through prose.

### TONE-044 Plain words

The right technical term only where the reader knows it; otherwise the plain word. No jargon invented
in the conversation.

## Language

### TONE-050 One language

Reply in the language the thread or issue already uses. New text: the language the caller passes,
else the language of the user's request. Never mix languages, except fixed product and technical
terms.

### TONE-051 One form of address (check: mixed du and Sie)

Inferred from context: the thread's existing address, how the reporter wrote, what the user said. Not
inferable and not told: `Sie` for external, `du` for internal. One form throughout a text. The same
applies to any language with a formal and informal you.
